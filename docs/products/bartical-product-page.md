# Bartical プロダクトページ仕様

## 目的

Bartical のプロダクトページは、メニューバーの項目を物理位置からまとめ、細い縦型メニューで呼び出せるコア体験を、ページを巡るナビゲーションとして実際に操作できる形で伝える。

製品仕様の正本は `/Users/workSpace/Bartical/docs/` とし、ページ内では次の正式用語を使用する。

- **ランチャー**: 左クリックで縦型メニューを開く、常時操作可能な Bartical 項目。
- **番号付き境界 / 設定用アンカー**: Command ドラッグで配置し、所属区間の右端を示す項目。
- **所属項目**: 同一ディスプレイ上で境界直前の物理区間にある外部アプリのメニューバー項目。

所属項目は設定へ記録・手動登録せず、境界との物理位置から自動判定する。Bartical が他アプリの項目を並べ替えるような表現は使用しない。

## ヒーローシミュレーション

- 画面上部に macOS のメニューバーを模した固定ナビゲーションを表示する。
- メニューバーはヒーローの主役として通常のサイトナビゲーションより大きく表示する。
- 右寄りに 3 つの Bartical ランチャーを、アプリ本体と同じ描画ロジックで生成した番号アイコン `3`、`2`、正式 SVG の順に置く。サイトの `BARTICAL` ワードマークはメニューバーへ重ねない。
- 正式 SVG のメインランチャー中心はデスクトップでviewport幅の約78%に固定する。展開時も同じ中心座標を維持し、設定用アンカーと元の所属項目だけをその左側へ一時復元する。デスクトップでは `③`、`②`、正式 SVG の中心間隔を 94px とし、macOS メニューバーに近い呼吸のある間隔で並べる。
- 3 つのランチャーはいずれも外側のカードへ入れず、透明な操作領域へアイコン単体で置く。`2` と `3` の角丸四角はカード装飾ではなく、Bartical 本体の `IconRenderer.numberedImage` と同じ番号アイコン資産とする。
- 右側の他アプリ項目は正式 SVG の中心から最初の項目までを 86px、以降を 72px の中心間隔で並べる。Lucide アイコンの見た目の大きさは正式 SVG と揃え、viewport端で項目を削除・再配置しない。右端を越える項目はそのままクリップし、ページ全体の横スクロールは発生させない。
- メニューバー内の正式なテンプレート記号は `/Users/workSpace/Bartical/Bartical/Assets/AppIcon/Bartical.icon/Assets/BarticalIconBody.svg` と同一内容の実行時SVGを使用する。
- Aboutとホームの製品カードには、実アプリの `ApplicationIconProvider` が読むビルド済み `Bartical.icns` から抽出した256pxの `BarticalAppIcon.png` を使用する。製品一覧だけは、同じ正式画像から透明な光学余白を除いた `BarticalCatalogIcon.png` を使い、画像領域いっぱいに直接表示する。どちらも独自の背景、反転、パディングでアプリアイコンを再構成しない。
- Barticalページのfaviconには、同じ `Bartical.icns` から抽出した32pxの `BarticalFavicon.png` を使用する。再書き出し用の一時スクリプトや中間生成物は `.temp/` で扱い、公開ソースや保守対象ツールには含めない。
- 番号ランチャーは `/Users/workSpace/Bartical/Bartical/Presentation/IconRenderer.swift` の `numberedImage` と同じ AppKit 描画から生成した `BarticalNumber2.png` / `BarticalNumber3.png` を使用する。
- 番号ランチャー以外の Bartical ではない UI アイコンは Lucide を使用する。
- 初期表示では正式 SVG のランチャーを選択し、その直下に LP セクションを元アプリ項目として見立てた縦型アイコン列を開く。
- ランチャーの再押下、メニュー外の押下、`Escape` で閉じる。別ランチャーを押すと、そのランチャーに対応する縦型アイコン列へ切り替える。
- 閉じているメニューは DOM の `hidden` 状態にして、キーボードのフォーカス順からも除外する。
- 縦型メニューはアイコンのみを基本とし、デスクトップでは hover / focus のラベル、全環境ではアクセシブル名とライブステータスで行き先を伝える。
- 縦型メニューの所属項目を選んだ時点では対応セクションへ直接移動しない。アプリ本体の `beginActivationReveal()` と同じく、格納に使う境界を通常幅へ戻して、すべての設定用アンカー、選択元ランチャーの縦型メニューに存在する元のメニューバー項目、操作可能な全ランチャーをヘッダーへ一時表示する。別ランチャーだけに所属する項目は、この一時表示へ混在させない。
- 一時表示へ切り替えても正式 SVG のメインランチャー中心座標は変えない。通常時のランチャー位置を基準に、復元したアンカーと所属項目を左方向へ展開する。
- 右側の他アプリ項目はアンカー展開中も消さず、通常時と同じ位置から右方向へ続ける。レスポンシブ規則で元から省略している補助項目だけは、その表示規則を展開中も維持する。
- 一時表示した元項目は縦型メニューと同じ Lucide アイコンを使い、選択元をmacOSメニューバーに近い白い半透明の横長ピルでハイライトする。ピルは項目の当たり判定や中心位置を変えず、アイコンの背面だけを左右へ広げる。縦型メニューの上から下の順番を、設定用アンカーに近い側から遠い側へ対応させるため、ヘッダーでは右から左へ同じ項目順で並べる。その直下に元アプリのメニューを模したメニューを開く。
- 元アプリメニューは対応セクションへ移動する主操作と「メニューを閉じる」だけに絞り、「別の所属項目を選ぶ」は置かない。メニューの左端は選択した元項目の左端へ揃え、狭いviewportで右端が収まらない場合だけ左右8pxの安全余白内へ移動する。主操作を選んだときに初めて対応セクションへ移動し、移動、メニュー外押下、`Escape`、または「メニューを閉じる」でメニューと一時表示を閉じ、通常の格納状態へ戻す。
- 一時表示中のランチャーを選ぶと元の項目とアンカーを再格納し、選択したランチャーの縦型メニューへ切り替える。
- ヒーロー本文の縦書き `BARTICAL` は使用しない。左側に実アプリの `AboutWindowController` を再現したAboutウィンドウを置き、正式アプリアイコン、製品名、`1.0.0(1)`、著作権、Webサイト `https://masashi-desu.github.io/products/Bartical` を表示する。製品コピーは次の Overview セクションへ移す。
- バージョン情報のWeb側の正本は `site/products/Bartical/appcast.xml` とする。About内の2つの表示はappcastの `sparkle:shortVersionString` と `sparkle:version` を読み、`<shortVersionString>(<version>)` 形式で同じ値を表示する。取得または解析に失敗した場合のみ、Bartical本体の `project.yml` と一致する `1.0.0(1)` をフォールバック表示する。
- Aboutウィンドウは縦型メニューから独立して初期表示し、メイン縦型メニューにAbout専用項目やLucide `Sparkles` は置かない。所属項目や表示設定を操作してもAboutは閉じず、About自身の赤い閉じる操作だけで非表示にする。
- ヒーロー背景は `hero-bg-dark.mp4` / `hero-bg-light.mp4` をテーマに追随して切り替え、ダークのベース色を `#181B3A`、ライトのベース色を `#EAF4FC` とする。映像はページ直下の背景レイヤーとしてviewport上端から配置し、メニューバー背面を含む動的viewport高（`100dvh`）へ収める。メニューバーは暗色の半透明面と24pxの背面ぼかしを組み合わせ、映像の連続性を残したままmacOSメニューバーのように前景アイコンを安定して読めるマテリアルとする。映像は装飾扱いで音声を持たず、`prefers-reduced-motion` では停止する。
- ヒーローの高さは固定の最低値を持たず、常に現在の動的viewport高からメニューバー高を引いた値とする。映像下端とヒーロー下端はviewport下端に一致させ、Aboutウィンドウは横位置を維持したまま、ヘッダーに覆われないヒーロー領域の垂直中央へ配置し、ヒーローの下へはみ出させない。
- メイン縦型メニューの末尾にLucide `Settings` の表示設定項目を、他の所属項目と同じ間隔・面・状態表現で置く。専用の区切り線や横出しポップオーバーは使用しない。
- 表示設定を選ぶと他の所属項目と同じ共通フローで設定用アンカーと元のLucide `Settings` 項目を一時表示し、その元項目の直下へLucide `Sun` / `Moon` のライト・ダークメニューを開く。選択はサイト共通の `mdw-theme` 設定へ反映し、選択後は元の格納状態へ戻す。
- ランチャー直下の縦型メニュー本体は、ヘッダーより少し濃い暗色半透明面と22pxの背面ぼかしを使い、macOSのポップオーバーに近い奥行きを持たせる。選択中・hover・focus の項目面とツールチップは可読性と操作状態の判別のため独立した面を維持する。
- デスクトップのメニューバーは 120px を基準とし、アイコンと縦型メニューを一体で拡大する。左端の戻る導線は可視テキストを置かず、Lucide `ArrowLeft` だけを表示しつつアクセシブル名を保持する。小さい画面では 80px、各アイコンの中心間隔を 48px へ縮小し、補助システムアイコンを省略して 320px 幅の操作性を維持する。

正式 SVG ランチャーの縦型メニューは次を含む。OverviewはAboutと同様に縦型メニューから独立させ、スクロールまたは元項目の操作で到達する。

1. しくみ `#how-it-works`
2. カスタマイズ `#customize`
3. プライバシー `#privacy`
4. 必要環境 `#requirements`
5. Coming Soon `#coming-soon`

縦型メニューはページ内の対象セクションと同じ上からの順序を正本とする。表示設定はページセクションではないため常に末尾へ置く。アンカー展開時は、この上からの順序を設定用アンカーに近い右端から左方向へ対応させ、右から「しくみ、カスタマイズ、プライバシー、必要環境、Coming Soon、表示設定」の順に復元する。補助ランチャーも、自身が持つ項目だけを同じページ順で表示・復元する。

`②` と `③` は複数 Bartical の独立性を体験させる補助ランチャーとして、それぞれ関連するセクションの短いメニューを開く。

## ページ構成

1. **Hero**: コピーを置かないシンプルな背景上で、操作可能なメニューバーシミュレーションだけを見せる。
2. **Overview**: ヘッダー下の動的viewport内へ収まる一画面構成とし、番号付き境界①・②を持つ配置シミュレーションを主役にする。境界は左から `② → ①`、右から `① → ②` の昇順で配置する。外部アプリアイコンは⌘ドラッグで境界をまたいで並べ替えられ、常に「右側で最初の境界」から所属を再計算する。各アイコンのhover／focusでは、①または②の番号アイコンと「①に所属しています」のような説明を表示し、どの境界より右にある場合は未所属と示す。デスクトップでは「散らかったメニューバーを、縦にしまう。」を一行で横へ伸ばし、物理位置からまとめる短い説明をその直下へ置く。小さい画面では自然改行を許可し、補助カードは置かない。
3. **How it works**: Overviewと同じ一画面構成で、「境界を置く → ランチャーを開く → 元アプリを操作」の3ステップだけを簡潔に見せる。
4. **Customize**: Overviewと同じ一画面構成で、Barticalを任意の数だけ作成し、それぞれをユーザーが個別設定できることを主訴求にする。ブランドの正式SVGはWebページ上のBartical表現にのみ使い、このセクションでユーザー設定例として提示しない。「名称」「アイコン（SF Symbols / 任意SVG / 番号）」「表示方法と色（Template / Original / Custom Color）」の3設定項目を同列に示し、用意済みプリセットから選ぶUIと誤認させない。
5. **Privacy**: Overviewと同じ一画面構成で、ローカル利用を一文で示し、外部送信なし、カーソル非介入、不正配置では格納しないフェイルセーフを3つの事実へ整理する。
6. **Requirements**: Overviewと同じ一画面構成で、macOS 14以降、Accessibility、Screen & System Audio Recording、10言語を2×2の要件表へまとめる。
7. **Coming Soon**: Overviewと同じ一画面構成で、配信開始前であることだけを短く示す非リンクのCTA。

## レスポンシブとアクセシビリティ

- 320px 幅まで横方向のオーバーフローを発生させない。
- OverviewからComing Soonまでの`01–06`は、すべて現在の動的viewport高からメニューバー高を引いた一画面の高さとする。各セクションは「番号付きキッカー＋短い見出し＋短い説明＋主役となる1つの図解」の共通リズムで情報を整理し、1440×900、1372×619、393×852、320×568の各表示領域内に主要内容を収める。
- 小さい画面では図解を縦方向のコンパクトな行、または2列グリッドへ組み替える。見出しと説明の意味、各機能・要件の事実は維持し、表示領域に収めるためだけに主要情報を非表示へしない。
- 小さい画面では補助システムアイコンと文字ラベルを段階的に省略するが、3 ランチャーと正式 SVG は維持する。
- すべてのランチャーは実際の `button` とし、一時表示中も操作可能な入口として維持する。
- 縦型メニューの所属項目と一時表示した元項目は実際の `button`、元アプリメニュー内のセクション導線も実際に操作できる `button` とし、二段階の操作順をARIAで伝える。
- ランチャーは `aria-expanded` と `aria-controls`、縦型アイコン列は固有の `aria-label`、状態説明は `aria-live="polite"` を持つ。
- `prefers-reduced-motion: reduce` ではスクロールと遷移アニメーションを無効化する。
- 固定メニューバー高を含むページ共通の`scroll-padding-top`に対し、各一画面セクションは追加の16px余白を`scroll-margin-top`で相殺する。ハッシュ遷移後のセクション上端をメニューバー直下へ揃え、表示中の縦幅をすべて内容へ使う。

## 配信導線

Bartical は未配信のため、製品一覧からはこの詳細ページへ接続するが、ページ内の配信 CTA は `Coming Soon` の無効状態とする。App Store、itch.io、GitHub Release など配信先へのリンクは設置しない。

Sparkleの公開URLは `https://masashi-desu.github.io/products/Bartical/appcast.xml` とする。配信開始前の `1.0.0(1)` はダウンロード用 `enclosure` を持たない `sparkle:informationalUpdate` とし、製品ページをリリース情報リンクに使う。

## アイコンアセットの保守

- 中央ランチャーは実アプリのメニューバー項目と同じ `site/products/Bartical/BarticalIconBody.svg` を参照する。製品カード、About、faviconはIcon Composerの正式書き出しを参照し、テンプレートSVGからWeb独自のアプリアイコンを合成しない。
- 番号ランチャーは Bartical 本体の `IconRenderer.numberedImage` と同じ式で高密度 PNG を生成し、`site/products/Bartical/BarticalNumber2.png` / `BarticalNumber3.png` を実行時資産として保守する。
- 製品カードでは、黒一色の正式 SVG をブランドグラデーション上の白いglyphとして表示し、ライト・ダーク両テーマで判読できる状態を維持する。
- Bartical 以外のUIアイコンは、`tools/bartical-lucide-entry.mjs` に列挙した Lucide subset から `npm run build:bartical-icons` で再生成する。
- 生成物は `site/vendor/bartical-lucide.min.js`、ライセンス表記は `site/vendor/lucide.LICENSE.txt` に置く。
