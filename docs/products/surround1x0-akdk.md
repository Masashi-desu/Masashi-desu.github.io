# Surround1x0-AKDK 商品ページ仕様

## 目的

`site/products/Surround1x0-AKDK/index.html` は、ホームと同じく 1 viewport を 1 メッセージとして扱う縦方向のセグメントページとする。実機の左右ユニットを常に体験の中心に置き、入力機能の統合、レイヤー設計、公開リポジトリへの導線を順番に伝える。

## セグメント構成

1. 左右ユニットを配置し、中央に「HIDの到達点」を表示する。
2. 左ユニットを左上かつ手前へ捻りながら退場させ、右ユニットを右側から手前へ大きく傾ける。左側の「キーボード、マウスカーソル、テンキーを統合。」は常にモデルより手前へ表示する。
3. 右ユニットを右上かつ手前へ捻りながら退場させ、左ユニットを左側から手前へ大きく傾ける。右側の「駆け抜ける入力。レイヤー切り替えのための頭脳。」は常にモデルより手前へ表示する。
4. 左右ユニットを再配置し、GLBに含まれる分解レイヤーを展開する。左にホームへ戻るリンク、右にGitHub リポジトリへのリンクを配置し、DOM順とキーボードフォーカス順も左から右へ一致させる。
5. ページ末尾のフッタを独立した設定セグメントとし、言語・テーマ設定を表示する。設定セグメントでは直前の `04` の3Dシーンを維持し、同一シーンへの移動は再発火させない。

デスクトップでは説明と実機を左右へ分ける。モバイルの第1セグメントでは説明を上、左右の実機を下へ配置し、両者の間隔を詰めたまとまりとして画面中央へ寄せる。第2・第3セグメントは縦長モバイルで実機を上、説明を下へ移し、左右には寄せず画面中央へ配置する。横向きモバイルは説明と実機を左右へ分ける。モデルは説明と画面端に余白を残した領域で可能な限り大きく表示する。いずれも指定メッセージの改行と主要リンクを 1 viewport 内に維持する。

## 3Dアセットと描画

- ライトテーマ: `site/products/Surround1x0-AKDK/assets/Surround1x0-AKDK-White.glb`
- ダークテーマ: `site/products/Surround1x0-AKDK/assets/Surround1x0-AKDK-Black.glb`

アクセントカラーは各モデルの球の方向性に合わせる。ダークテーマは赤（`#ff344a`）、ライトテーマはシルバーグレー（`#686d75`）をUIへ使用し、ナビゲーションの選択表示、ラベル、リンク、フォーカス表示、3Dモデルのリムライトを同系色で統一する。
共通テーマCSSが製品CSSより後に読み込まれる本番ビルドでも、製品固有のアクセント指定が共通のホーム用アクセントに上書きされないようにする。
- 描画: Three.js と `GLTFLoader`

各 GLB の `Left_Half_Root` と `Right_Half_Root` を独立して移動し、モデル形状の加工や疑似アセットへの置換は行わない。モデルの単位はミリメートルとし、ページ側の表示制御ルートで `0.001` 倍してメートル相当へ正規化する。通常のセグメント間移動は横方向の平行移動に見せず、行程の前半へ頂点を置いて浮き上がり、目標へは上方かつ手前側から降りる三次ベジェ曲線の弧で位置・奥行き・大きさを補間する。姿勢の補間には次の3層を重ねる。(1) 回転差分の約8%を行程60%付近で頂点にして戻すベル状オーバーシュート、(2) 移動量に比例して進行方向へ傾くピッチ・ヨー・ロールのバンク（その軸自体の姿勢変化が大きい移動では減衰させる）、(3) 退場と同じ対角軸を使う一過性のコーナーtwist（基準twistが大きく変化する移動では減衰させる）。所要時間は移動量に応じて伸縮させ、退場する側または移動量の大きい側のユニットを先行させて、もう一方をデスクトップ約110ms・モバイル約70msの遅延で追従させる。左右の移動量が等しい対称な移動では遅延を加えず対称性を維持する。再入場するユニットの透明度は行程の前半30%で不透明へ戻し、飛行中の姿を見せる。透明化が完了して駐機しているユニットの再入場は、遠い退場ポーズからではなく画面端付近のステージング姿勢から開始する（透明な状態での位置替えのため知覚されず、フェードインしながら降りるため、ビューポートのアスペクト比によらず早期に画面へ現れる）。再入場の前半は持ち上げの弧を使わず目標へ直進し、着地側のみ上方かつ手前からの弧で降りる。これにより退場側が画面から消える前に再入場側が画面内へ入り、セグメント移動中に左右ユニットが同時に画面から消えて何も表示されない瞬間を作らない。セグメント 2 / 3 間の退場は専用の三次ベジェ曲線で位置・奥行き・回転・大きさを補間する。いずれも `smootherstep` 系の曲線で開始・停止時の速度と加速度を0へ収束させ、スケールの終端オーバーシュートや跳ね返りは加えない。3Dは単一canvasへ描画して二重描画による合成アーティファクトを避け、全セグメントのコピー、リンク、案内テキストをそのcanvasより上のレイヤーへ置いて可読性を優先する。テーマ切り替え時は `document.documentElement.dataset.theme` を監視し、対応するモデルへ切り替える。

第4セグメントでは、GLBの各レイヤールートに記録された `exploded_view_order` と `site_exploded_spacing_mm` を読み取る。底ケースを基準に、コントローラー／マウスセンサー、コンスルー／ホットスワップソケット、PCB、トップケース、スイッチ、キーキャップ、トラックボールの順にGLBのローカルZ軸方向へ展開する。全レイヤーを同時に動かさず、左右と高さの順序を組み合わせた位相差を付けて分解する。キーキャップとキースイッチを先行させ、上部ケース、ホットスワップソケット、コンスルー／PCB類の順に動かす。キーキャップ、キースイッチ、ホットスワップソケットはレイヤー全体を一括移動せず、GLB内の各個体ノードを上段から下段、各段の左から右へ順に遅延させ、同じ種類のパーツ内にも波を伝える。ソケットは従来より個体間の遅延幅を短くして早く離脱させる。コンスルー、ソケット、PCB、コントローラー、マウスセンサーの移動量は、同じ側の上部ケース移動量の78%以下へ常時制限し、移動中も上部ケースを追い越さず干渉しないようにする。コントローラー、マウスセンサー、コンスルー、PCBは機能単位のアセンブリを維持し、その内部構成部品は分離しない。分解状態で左右半体を捻る移動では、各パーツを半体ルートの角度へ完全同期させず、分解波の順序に沿った短い位相差と最大約3.2度の追従角を加える。キー系は追従差をやや大きく、PCBやケースなど面積の大きい部品は小さくして干渉を避け、移動の終端ではすべての追加角度を0度へ滑らかに収束させる。分解波は第4セグメントへの移動開始と同時に始める。第4セグメントへ再入場する非表示ユニットは、汎用の拡大済みステージング姿勢を使わず、画面比率に応じて決まった目的地と同じスケールのまま外側から移動し、移動中に巨大なユニット同士が重なったり貫通したりしないようにする。

縦長・正方形のモバイルの第4セグメントでは、幅338〜446pxの範囲で左右半体をカメラ方向へ寄せ、希望スケールを連続調整する。左右間隔と最終スケールは第1・第4セグメント共通の画面内フィット規則で決め、左右ともヨーとロールを加えない平行配置にする。高さ619〜844pxの範囲ではモデルの下方移動量、分解軸のピッチ、分解間隔を連続調整し、分解間隔を通常の2.45〜2.85倍に補正する。左右の距離、ピッチ、スケールは同じ値とし、狭い画面でも対称性、平行性、左右間の空間を維持する。

第4セグメントは画面幅が高さを超えた場合だけ横向きの分解表示へ切り替える。左ユニットは左下、右ユニットは右上へ展開する。各部品は元の分解軸上を真っすぐ移動し、部品ごとに平面方向へずらしたり独立した列へ並べ直したりしない。`surround-3d.js` 冒頭の `LANDSCAPE_EXPLODED_ROTATION_DEG` で、左右それぞれのXYZ Euler角を度数で指定する。左はX=68.93°／Y=8.59°／Z=39.74°、右はX=26.35°／Y=6.31°／Z=-40.68°とし、後段で右だけ追加回転を掛けない。右の角度は参照画像のキー中心とトラックボール位置をGLB実座標へ対応させて求めた姿勢を使用する。モバイルではカメラのピッチ差だけ補正する。横長時の画面内フィットはGLBの元の組み立て角度を含めた分解軸を投影する。各レイヤーの実頂点から凸包を作り、球や斜めのケースを囲む箱の空き領域を外側の余白として残さない。分解間隔は画面比率1:1〜4:1に応じて通常の0.85〜1.6倍へ連続調整する。横長時は左右端と左右ユニット間の固定マージンを0pxにし、分解部品の投影範囲が重ならない最大の共通スケールで表示する。左右のX位置の対称性と共通の上下位置による制約を外し、それぞれの投影範囲を左端／右端へ追従させて上下中央に配置する。上下にはPC24px／モバイル16pxの余白を保ち、左右が接するか一方の高さが上限に達するまで拡大する。元の角度と部品の分解軸は維持する。縦長・正方形のPCとモバイルは従来の縦方向の分解姿勢と間隔を維持し、回転やウインドウのリサイズ時に切り替える。

第1〜第3セグメント間の通常移動では分解レイヤーへ位相差を付けず、左右それぞれを組み立て済みの剛体として移動する。第4セグメントから別セグメントへ移るときは分解状態を即時解除せず、左右ユニットの移動と並行して分解時と逆順の波で徐々に組み立てる。組立完了後の第1〜第3セグメント間移動では再び波を発生させない。`prefers-reduced-motion` では分解・再組立とも位相差を付けず最終状態を即時反映する。

セグメント 2 / 3 間の退場は横方向の直線移動にしない。退場ユニットは画面内にいる前半で上昇、カメラへの前進、捻りを先行させ、後半は横滑りせずに画面上側の角（右ユニットは右上、左ユニットは左上）からカメラの脇を抜けるように退場する三次ベジェ軌道を通る。横方向の到達距離は縦方向と同程度まで抑え、奥行きの前進を主体としてこちらへ迫る印象を作る。移動中は縮小せず、カメラへ近づく動きとスケールの単調な拡大で画面を覆いながら抜ける（モバイルも縮小しない）。姿勢はモデルの奥側（画面上側）を `rotationX` で大きくこちらへ傾け、`rotationY` のヨーを退場側の側面（右ユニットは右側面、左ユニットは左側面）が見えるまで深く回頭させる（デスクトップ約-1.25rad、モバイル約-1rad）。この姿勢回転はtwistと同様に行程の前半約45%で開始・停止速度0のまま完了させ、側面が見える回頭を画面内で見せ切ってから軌道に乗って抜ける。再入場は同じ姿勢から正面へ巻き戻す。GLB上の右奥角はローカル`(+X, -Z)`、左奥角は`(-X, -Z)`にあるため、右は`(+X, +Z)`対角軸、左はその鏡像軸を使うQuaternion twistを補間する。このtwistは退場時間の前半42%で開始・停止速度を0に保ちながら完了させ、対象の奥角が画面端へ達するまでに中心よりカメラ側へ起き上がるようにする。右ユニットは右奥角、左ユニットは左奥角を手前へ起こしながら、それぞれ右上・左上へ退場する。左右はX位置、対角軸、回転角の符号を反転した鏡像とする。退場モデルの透明化は軌道の68%以降に開始し、斜め移動、前進、奥角の捻りが視認できる時間を確保する。入退場の透明度は左右ユニットごとに複製したThree.jsマテリアルへ反映し、反対側の非表示ユニットが完全不透明で一瞬描画されることを防ぐ。モバイルも距離を縮めた同じ方向性の軌道を使用する。

WebGL または GLB 読み込みに失敗した場合も、写真へ切り替えない。ローディング表示を終了し、コピーとナビゲーションを維持する。WebGL context喪失時は3D canvasも非表示にする。写真フォールバックのDOM、CSS、表示処理は設けない。

第1セグメントでは左右ユニットを中央へ寄せ、筐体前面よりキー面と天板が主に見える、真上に近い俯瞰角度へ傾ける。横方向の振り角と傾きは加えず、左右の上辺とキー列を同じ水平線へ平行に揃える。中央の「HIDの到達点」の背後へ一部が回り込む配置で、製品の横幅、入力面、工業製品としての精度を最初に印象づける。

第1セグメントと縦長・正方形の第4セグメントの静止配置では、左右ユニット間の最小マージンをデスクトップ24px、モバイル16pxとし、画面四辺にも同じ最小マージンを確保する。GLBの各メッシュの境界を画面へ投影し、第4セグメントでは分解後の部品位置も含めて計算する。両テーマとポインターによる視点移動の範囲全体でマージンを守る最小の対称X位置へ寄せ、縦長・正方形では希望スケールで収まらない場合だけ左右を同率で縮小し、横長では最大まで同率で拡大する。画面の幅・高さが変わるたびに再計算し、縦長のPC画面でも筐体や部品を見切れさせない。672px以下の縦長・正方形ではモバイル専用の高さ・姿勢・希望スケールを使用する。セグメント間の入退場アニメーションは画面外を通過できる。

第1セグメントが横長（画面幅が高さより大きい）の場合は、希望スケールの上限を外す。左右の最小間隔と画面端のマージンを保ち、上部ナビゲーションの下端とスクロール案内の上端からも同じマージンを確保した領域内で、左右ユニットを可能な限り大きく表示する。スクロール案内を表示しないモバイル横向きでは画面下端を使う。投影されたモデル全体をこの領域の上下中央へ寄せ、幅または高さの制限に達する最大の共通スケールを求める。別セグメントから戻る際も案内位置はセグメント内の座標で測り、スクロール途中の位置に左右されない。横長表示ではモバイルもこの中央配置を優先する。

第2・第3セグメントの説明枠は全画面幅に追従させ、左のコピーは左端、右のコピーは右端からデスクトップで最低24px（通常のページ余白が広い場合はそちらを使用）、モバイルで16pxを確保する。デスクトップの文字領域は画面幅に応じて最大56remまで広げ、最大文字サイズでも第2の指定3行と第3の1行を不自然に折り返さない。左右の表示領域の間には24px以上を残す。

第2・第3セグメントは、固定スケールの上限を使わず、注目する右／左ユニットを表示領域の中央で最大まで拡大する。GLBの実頂点から組み立て状態の凸包を求め、両テーマとポインター視差を含む投影外形で判定する。ナビ下端・画面端・説明文との間にデスクトップ24px／モバイル16px以上を残す。デスクトップと横向きモバイルでは説明文の横、縦長モバイルでは説明文の上の領域へ収める。説明文は行ごとの表示範囲を測り、非表示時の出現アニメーションとスクロール位置を除いて計算する。リサイズ・言語変更・フォント読込後に配置を更新する。退場先のスケールは現在の表示倍率の1.16倍以上に補正し、大きな表示からも縮小せず退場する。

## 操作と検証

- セクションのスクロール・位置合わせと左右モデル／分解レイヤーのアニメーションがすべて完了した後、モデル操作を有効にする。ロード中、移動中、描画失敗時、フッタ設定では操作領域を無効にする。操作ボタン、ツールバー、常設の操作説明は表示しない。
- 各キーボードを左ドラッグすると、その側だけを画面の縦横軸に沿って回転する。ミドルドラッグでは画面と平行な面内を移動する。タッチは1本指で回転、2本指の重心移動で平行移動する。移動量は基準位置から各軸±0.3（表示空間）以内に制限する。
- モデル操作領域上のタッチはセクション移動へ渡さず、背景スワイプと通常のホイールは従来のセクション移動を行う。リンク・コピー・上部ナビゲーションを操作領域より手前へ置く。ドラッグ中のホイールはセクション移動を起こさない。
- モデルはTab／Shift＋Tabで選択でき、その選択中だけテーマに対応するフォーカス枠を表示する。マウス・ミドルボタン・タッチの操作開始時とフォーカス解除時に枠を消す。ドラッグ開始時のプログラムによるフォーカスでは枠を表示せず、Escapeなどのキーボード操作を受け取れる状態は維持する。
- フォーカスしたモデルは矢印キーで回転、Shift＋矢印キーで移動でき、Escapeで現在のセクションの標準配置へ戻す。スクリーンリーダーにはこの操作説明を提供する。テーマを変更してもユーザーの姿勢を維持する。別の3Dシーンへ移るときは操作中の姿勢から新しい標準配置へアニメーションし、リサイズ時は画面に合う標準配置を再計算する。各セグメントの最小マージンは標準配置に適用し、ユーザー操作中は自由な回転・移動を優先する。
- `npm run test:surround-segments` では左ドラッグ・ミドルドラッグ・1本指回転・2本指移動・キーボード操作を検証し、Tab／Shift＋Tabでの枠表示とポインター操作時の非表示、操作ボタンが存在しないこと、配置中の操作拒否、退場モデルの操作領域非表示、分解間隔・テーマ変更時の姿勢維持、背景スワイプとの共存も確認する。
- 上部の `01`〜`04` と歯車の設定セグメント、マウスホイール、タッチ操作で各停止位置へ移動できる。
- URL hash は現在のセグメントと同期する。
- GLB読込中もセグメント移動を受け付け、読込完了時は最新の選択位置へモデルを配置する。遅延したGLB応答中に複数回移動する回帰テストで確認する。
- セグメント制御中はCSSの `scroll-behavior` を `auto` にし、通常の移動だけJavaScriptから明示的に `smooth` を指定する。最終位置合わせには即時スクロールを使い、WebKitで位置合わせが繰り返しアニメーションされて操作待ちになることを防ぐ。横長WebKitのスクロール回帰テストは3D描画から独立させ、CIのネイティブGPUに依存せず停止位置への収束を検証する。実描画とモデル操作はmacOSの本番ビルド確認でも検証する。
- 既存の言語設定、テーマ設定、遷移元に応じた戻り先を維持する。
